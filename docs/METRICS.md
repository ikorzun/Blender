# Метрики «Миксера» — базовый набор для казуальной игры

Спека, 2026-07-28. Заказ владельца: «сколько времени провёл игрок на экране,
куда кликал, где успех, а где отвалы; базовый набор для казуалки; логи крешей
и их анализ».

---

## 0. Принципы (почему набор именно такой)

1. **Каждая метрика отвечает на решение, которое мы примем.** Метрика, под
   которую нет действия, — шум. Ниже у каждой группы написано, что мы с ней
   делаем.
2. **Воронка важнее счётчиков.** «5000 матчей» ничего не говорит; «из 100
   открывших игру до 3-го уровня дошли 41» говорит, где чинить.
3. **События маленькие и редкие.** Мобильный трафик: батч раз в 12 событий +
   на уходе со вкладки (уже так работает). Никаких покадровых отправок.
4. **Никаких персональных данных.** Только анонимный `sid` сессии. Ни IP-
   геолокации, ни идентификаторов устройства, ни данных площадки.

---

## 1. Что уже есть (19 событий, транспорт готов)

`79-telemetry.js`: батчи `sendBeacon`, анонимный `sid`, флаш при уходе.
⚠️ `URL = ''` — **телеметрия выключена**, события никуда не идут. Включение =
одна строка (воркер Cloudflare, как на лендингах).

Экономика и реклама покрыты: `level_start`, `win`, `lose`, `spend`, `rw`
(shake/hint/x2/continue/detector), `inter`, `boost`, `unlock_buy`,
`bundle_buy`, `acc_up`, `continue`, `stars_migrate`.

## 2. Чего НЕТ и что добавляем

| Дыра | Что добавляем |
|---|---|
| Время на экране | `screen` (вход/выход + длительность) |
| Куда кликал | `tap` (сектор экрана + попал/промах) |
| Отвалы | `quit` (уход со вкладки + контекст) |
| Креши | `err` (ошибка + стек + контекст) |
| Первая сессия | `fts` (шаги первого прохождения) |
| Здоровье клиента | `perf` (кадры/память, раз в сессию) |

## 3. Экраны и время на них

**Событие `screen`**: `{n:'screen', v:'<имя>', ms:<сколько пробыл>, lv:<уровень>}`
шлётся при УХОДЕ с экрана (тогда известна длительность).

Экраны: `intro` · `game` · `pause` · `win` · `menu` · `collection` ·
`more_stars` · `ad` · `museum`.

**Что решаем.** Если на `more_stars` медиана < 2 с — экран не читают, виновата
подача, а не цена. Если `win` держат дольше 6 с — экран мешает темпу, надо
ускорять переход. Если `intro` > 8 с — облёт длинный, резать.

## 4. Куда кликал

**Событие `tap`**: `{n:'tap', z:'<зона>', r:'<результат>', lv, t:<мс от старта уровня>}`

- зона `z`: сетка 3×3 по экрану (`tl,tc,tr,ml,mc,mr,bl,bc,br`) — не координаты,
  чтобы не плодить данные и не зависеть от размера экрана;
- результат `r`: `match` (совместил) · `miss` (промах) · `rock` (камень) ·
  `surprise` · `ui` (кнопка) · `dead` (пустое место).

**Что решаем.** Доля `miss` по зонам = карта промахов: если промахи копятся в
`bc` (низ-центр), значит палец закрывает предметы — поднимать камеру или
двигать HUD. Если `ui`-тапы часто рядом с кнопкой, но не по ней — мелкая зона
нажатия.

⚠️ **Не координаты, а сектора.** Точный heat-map требует нормировки под сотни
разрешений и хранит на порядок больше; для решений хватает 9 секторов.

## 5. Воронка и отвалы

**Событие `quit`**: `{n:'quit', v:'<экран>', lv, ms:<длительность сессии>, st:'<состояние>'}`
шлётся на `visibilitychange → hidden` (тот же момент, что и флаш).

Состояния `st`: `playing` (бросил посреди уровня) · `stuck` (бросил в тупике,
`level.deadlock`) · `after_win` (ушёл сразу после победы) · `on_offer` (ушёл
на экране покупки) · `on_ad` (ушёл во время рекламы).

**Ключевая воронка первой сессии** (событие `fts`, шаг в поле `k`):
```
open → intro_done → first_tap → first_match → level1_win → level2_start → level3_win
```
**Что решаем.** Провал между `first_tap` и `first_match` = не понял правило,
нужна подсказка на старте. Провал на `level2_start` = победа не мотивирует,
экран победы или награда слабые. `st:'stuck'` в заметной доле = выручалка
включается слишком поздно.

## 6. Креши и ошибки

**Событие `err`**: `{n:'err', m:<сообщение>, f:<файл:строка>, st:<стек, 3 кадра>,
lv, v:<экран>, b:<версия сборки>, w:<webgl-контекст жив?>}`

Ловим три источника:
1. `window.onerror` — синхронные ошибки;
2. `unhandledrejection` — упавшие промисы (загрузка ассетов, реклама, bridge);
3. `webglcontextlost` — **самый частый «креш» в 3D на мобильных**: игра не
   падает, но чернеет экран; без отдельного события выглядит как «просто ушёл».

**Правила, чтобы не утонуть в шуме:**
- дедупликация: одинаковая сигнатура (`m`+`f`) шлётся **раз за сессию**;
- потолок 5 ошибок на сессию — дальше молчим (защита от бесконечного цикла);
- отправка **немедленная** (не ждём батча): игра может умереть следующей же
  строкой.

**Анализ.** Группируем по сигнатуре, сортируем по «сессий затронуто» (не по
числу событий — один цикл ошибок в одной сессии не должен выглядеть эпидемией).
Смотрим срез по версии сборки: всплеск после релиза = регрессия, откатываем.

## 7. Здоровье клиента

**Событие `perf`** раз за сессию (на 60-й секунде игры):
`{n:'perf', fps:<медиана>, worst:<худший кадр>, mem:<МБ>, dpr, w, h, gl:<рендерер>}`

**Что решаем.** Если у 20% сессий медиана < 30 кадров — нужен «лёгкий режим»
(меньше предметов/эффектов). Поле `gl` покажет, на каких GPU беда.

## 8. Сводные показатели (что смотреть еженедельно)

| Показатель | Как считается | Тревога |
|---|---|---|
| Проходимость уровня | `win` / `level_start` | < 70% |
| Отвал первой сессии | нет `level1_win` среди `open` | > 45% |
| Время до первого матча | `fts:first_match` − `open` | > 25 с |
| Доля тупиков | `st:'stuck'` / сессии | > 8% |
| Промахи | `tap.r='miss'` / все тапы | > 25% |
| Досмотр рекламы | `rw` / запросов ролика | < 80% |
| Конверсия витрины | `bundle_buy` / `screen:more_stars` | — база |
| Сессий с ошибкой | сессии с `err` / все | > 1% |

## 9. Как вести (инфраструктура)

**Приём.** Cloudflare Worker (как на лендингах владельца) → пишет батчи в
хранилище. На старте достаточно: endpoint + запись в лог/таблицу.

**Хранение.** Одна плоская таблица событий: `t, sid, n, lv, v, …payload`.
Агрегаты считаются запросами, не заранее — набор вопросов будет меняться.

**Приватность.** Только `sid` (случайный, живёт сессию). Никаких id
устройства, кабинета площадки, IP-геолокации.

⚠️ **Площадки.** У Playgama/Yandex есть СВОЯ аналитика — часть показателей
(установки, ретеншн D1/D7, платежи) корректнее брать оттуда, а не считать
самим. Наш слой отвечает на вопросы про ИГРУ (где отваливаются, куда жмут,
что падает), а не про магазин.

---

## 10. Порядок внедрения

1. **Сначала креши** — единственная группа, которая ловит потерю денег молча.
2. Затем `screen` + `quit` — дают воронку и отвалы.
3. Затем `tap` — карта промахов.
4. `perf` — когда появится реальный трафик с разных устройств.
5. Endpoint включаем **последним**, когда есть куда принимать.
